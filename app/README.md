# CrowdScope demonstration

## Calibrated framework evidence and replay

Open `http://127.0.0.1:8770/framework.html` while the server is running, or use
`python app/launch.py --page framework.html`. The launcher selects this page by
default when the local recorded-data package is present; otherwise it opens the
original self-contained synthetic demo below.

A clean checkout can still open `framework.html`: it shows included aggregate recognition/calibration results and usage guidance instead of participant trajectories. `framework_results.js` is aggregate-only and is included.

This new page uses recorded SiME positions and calibrated probabilities from a
coherent model that excludes the replayed trial. Participants may repeat in its
training recordings. Four-second histories are scored at the validated x=-1
crossing; earlier occupants retain a flagged prior. The browser plays saved
outputs from the streaming pipeline and recomputes hypothetical allocations as
controls change. It does not run CCTV, a new movement simulator or browser-side
model training. Budget/capacity/request-rate changes do not modify the detector.

`framework_data_LOCAL_ONLY.js` contains participant-level derived records and is
ignored by Git. It is generated by `research/evaluate_calibrated_framework.py`
after calibration. A checkout without the authorised source data cannot recreate
the recorded replay from synthetic files. See `docs/calibrated_framework.md`.

## Original synthetic demonstration

Run `python app/launch.py --page index.html` from the repository root, or open `app/index.html` directly. The app is self-contained: no CDN, account, backend inference service or network upload is required. Local address: `http://127.0.0.1:8770/index.html`.

The replay shows **synthetic JuPedSim trajectories**, not recorded human tracks or live detection. Its initial 80 agents pass through a 1.2 m entrance. The underlying development run remains timestep-sensitive; the animation does not validate an evacuation forecast.

Controls let you scrub/play the replay, change the working information representation, budget, assumed prevalence and assumed observation error. Zone density uses usable area; speeds use adjacent past replay samples. Each unit provides capacity for two hypothetical requests. Fixed request rates are 0.1/0.4. Stored observation bits have 20% noise; changing the assumed error does not regenerate them. Optional profile colours display simulation truth, never recognised disability.

The JavaScript allocator uses the same Poisson-binomial expected-shortfall formulation and exhaustive lexicographic allocation search as the Python planner. A separate check compared 100 seeded Python/JavaScript fixtures. `check_planner.cjs` accepts a JSON fixture file with `groups`, `budget`, `capacity` and Python `expected` results.

`demo_data.js` contains only a synthetic replay and its generated profile/observation metadata. The source is the saved `room_w1.2_jitterTrue` development case at dt=0.005 s; frames are sampled every 0.5 s for display. The final empty frame follows the verified all-agent exit ledger. No person-level SiME data is bundled.
